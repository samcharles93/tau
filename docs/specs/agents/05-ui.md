# UI: Rendering Child Agents

Design constraints, both standing tau principles: state-not-log (the tui2 north star), and TUI/WebUI must not drift.
Both surfaces therefore render from the same data: the child's full event stream, forwarded by the parent through the
bridge in agent-scoped envelopes. The UI chooses how much to _show_; nothing is withheld from it.

## Event flow

```
child coordinator ── ChatEvents ──> child stdio ── agent.event ──> parent
parent re-publishes onto its bus, scoped to the spawning tool call
   ├──> TUI renders state block / drill-down
   └──> server bridge ── WebSocket ──> WebUI renders the same
```

The parent tags each re-published event with the child's instance address and the spawning tool-call id. The bridge
forwards them inside the agent-scoped wrapper (see 03, `agent.event`), so browser clients receive exactly what the TUI
receives.

## The state block

While a child runs, the spawning tool call renders as a compact live element, one per child, stacked when a turn fans
out:

```
▶ agent research#k3v9qp   reading internal/store/sqlite_store.go   turn 4 · 12.3k · 8s
▶ agent research#m2xw01   grepping "parent_session_id"             turn 2 ·  4.1k · 8s
```

Contents, all derived from the forwarded events and usage messages:

- Agent name and instance id, tinted with the spec's `color` when set
- Current activity: latest tool execution (verb + primary argument) or "thinking" with the tui2 shimmer treatment while
  a provider call streams
- Turn count and running token/cost figures (from `agent.usage`)
- Elapsed time

Terminal states collapse the block to a single summary line (status, turns, tokens, duration) above the tool result.
Abnormal ends colour the status and keep the line visible.

## Drill-down

One keypress (TUI) or click (WebUI) on a state block expands the child's transcript, rendered with the same message
components as a normal session view, fed from the forwarded events already held in memory. The durable record is the
child's session in the store: from the expanded view the user can open the child session proper (which also survives
restarts; live drill-down memory does not need to).

## Session tree

The sessions list gains lineage awareness:

- Child sessions display under their parent (indent or tree glyphs), using `parent_session_id` / `ListChildren`.
- Each row shows the agent identity that ran it (`agent_instance_id` joined to the instance row), so a session is always
  attributable to a spec + instance.
- Resuming a child session from the list is the manual counterpart of the `resume` spawn parameter.

## Cancellation affordance

While children run, cancel (Esc in the TUI, stop button in the WebUI) targets the parent turn, which propagates
`agent.cancel` down the tree (see 02). Cancelling a single child from its state block is a v1-optional nicety; if cheap
it sends a targeted `agent.cancel`, otherwise it can wait.

## Non-goals in v1

- No separate "agents panel" or dashboard; children appear where the work happens, inside the conversation.
- No attach-to-foreign-agent UI (requires the socket transport, deferred).
- No live editing of a running child's parameters.

## Recovery on reconnect and restart

Child drill-down state lives in memory while the TUI/WebUI is connected. On disconnect or restart, that in-memory state
is lost. Recovery reconstructs it from durable storage:

1. **On reconnect**: the bridge replays the last `ChatSessionSnapshotEvent`. This includes all completed tool calls and
   their child instance IDs. The UI renders completed child state blocks from the snapshot's tool records.
2. **Active children**: any child instances with `ended_at IS NULL` are queried from the store
   (`ListAgentInstances(parentInstanceID)`). The UI re-subscribes to the event bus for new events from those instances.
   Events emitted during the disconnect window are lost (see 03, Delivery guarantees - no replay in v1).
3. **Drill-down state**: expanded transcripts are reconstructed from the child's persisted session, not from the lost
   event stream. The UI opens the child session from the store.
4. **New connects** (browser refresh, new terminal): the same reconstruction path applies. No prior in-memory state is
   assumed.

**TUI and WebUI must recover equivalent state.** Both surfaces query the same store and receive the same event bus
subscription. The only difference is rendering.

## Bounding high-volume fan-out

When many children run concurrently, each emitting events at turn cadence, the in-memory event buffer can grow
unbounded. The UI applies bounded retention:

| Limit                                                    | Value                                                                                           | Behavior when exceeded                                                                                                                                                                   |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Max expanded children**                                | 8                                                                                               | When a 9th child drill-down is opened, the oldest expanded child transcript is collapsed to its state block. The full transcript remains available by re-opening from the session store. |
| **Max state-block events per child** (in memory)         | 256                                                                                             | Events beyond this are dropped from the live buffer. The child's session in the store is the authoritative record.                                                                       |
| **Delta coalescing**                                     | Consecutive tool-execution events of the same type within 500ms                                 | Collapsed into a single "N tool calls" summary line instead of individual entries. The full detail is available via drill-down.                                                          |
| **Max visible state blocks** (when ≥ 16 children active) | The 16 most recent children are shown; older ones are collapsed to a "+N more children" summary | The summary is clickable to expand.                                                                                                                                                      |

## Stable event ordering

When multiple children run concurrently, their events are interleaved in the parent's event bus by arrival time. The UI
must preserve stable ordering:

- **Per-child ordering is guaranteed**: events from child A arrive in the order child A emitted them (byte-stream
  guarantee).
- **Cross-child ordering is NOT guaranteed**: events from child A and child B may arrive in any order depending on OS
  scheduling.
- **UI render order**: state blocks are rendered in the order the `agent` tool calls were made by the model (the
  tool-call sequence in the parent's turn). This is stable and deterministic even when cross-child event interleaving
  varies.
- **Drill-down ordering**: within a child's expanded transcript, events are rendered in arrival order, which IS the
  child's emission order.

## Accessibility requirements

Both TUI and WebUI must remain usable under all of these constraints:

| Constraint                                    | TUI behavior                                                                                                                                                                                                                                      | WebUI behavior                                                                                                                                               |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Narrow terminal (< 80 columns)**            | State blocks truncate to fit: agent name and activity verb only. Full detail available via drill-down. Input area shrinks to single-line.                                                                                                         | Responsive layout: state blocks stack vertically at narrow widths.                                                                                           |
| **Keyboard-only operation**                   | All interactions reachable via keyboard: Tab to cycle state blocks, Enter to expand/collapse, Esc to collapse/navigate up. No interaction requires a mouse.                                                                                       | Tab-indexed state blocks, Enter/Space to expand, Esc to collapse. All interactions meet WCAG 2.1 AA keyboard requirements.                                   |
| **Screen reader / plain text**                | All state block information is available as text (no purely visual indicators). The activity verb, agent name, turn count, and status are plain strings. The shimmer animation is an `aria-hidden` decoration with a text fallback ("thinking…"). | ARIA labels on state blocks: `role="status"`, `aria-label="agent research#k3v9qp: reading file, turn 4"`. Status changes announced via `aria-live="polite"`. |
| **Reduced motion** (`prefers-reduced-motion`) | Shimmer animation disabled; replaced with static "thinking…" text. State block expand/collapse is instant (no animation). Tool execution spinner is a static character.                                                                           | CSS `@media (prefers-reduced-motion: reduce)` disables all child-state animations and transitions.                                                           |
| **Color-independent status**                  | Status is conveyed by both color AND a text label or icon character. The status line uses symbols (✓ completed, ✗ failed, ⚠ cancelled, ⏱ timed out) alongside color.                                                                              | Status badges include text labels, not color-only indicators. WCAG 2.1 AA contrast ratios on all status colors.                                              |
| **High contrast**                             | Respects terminal theme; no hardcoded ANSI colors that conflict. Spec `color` field is a tint, not a sole differentiator.                                                                                                                         | Supports `prefers-contrast: more` and browser high-contrast mode.                                                                                            |

## Parent cancellation reachable during drill-down

When a user expands a child transcript (drill-down), the UI must keep the parent turn's cancellation affordance
reachable:

- **TUI**: Esc first collapses the drill-down (if expanded). A second Esc (or Esc when no drill-down is expanded)
  cancels the parent turn. Alternatively, Ctrl+C always targets the parent turn regardless of drill-down state.
- **WebUI**: The stop button (top-level) remains visible and active even when a child transcript is expanded. The stop
  button always targets the parent turn.
- **Deep drill-down** (child → grandchild): Esc collapses one level at a time. Ctrl+C (TUI) or stop button (WebUI)
  cancels the root parent at any depth.
